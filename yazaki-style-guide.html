Accessibility Notes

Contrast and usability considerations for the Yazaki palette.

Brand Primary Contrast Warning

The brand primary color #ed1c24 on a white background has a contrast ratio of approximately 4.0:1, which fails WCAG AA for normal-sized text (requires 4.5:1).

Recommendations:

  • Use the darker variant #a01018 (--brand-primary-dark) for text on white backgrounds.
  • Use white text on #ed1c24 backgrounds (passes AA at 4.0:1 for large text / bold 14px+).
  • Reserve #ed1c24 for large headings, icons, and decorative elements where AA Large applies.

Mobile Design Guidelines

Best practices and token overrides for mobile (≤ 480px) experiences in the Yazaki application.

Mobile-first approach

Mobile layouts use a single-column structure with 16px layout margins. All interactive elements must meet minimum 44×44px touch targets. The base font size increases to 16px to prevent iOS auto-zoom on input focus.

Best Practices

check

Use 16px minimum for body text and inputs

iOS Safari auto-zooms the viewport when a user taps an <input> with font-size below 16px. Setting --font-size-default: 16px on mobile prevents this disorienting behavior.

check

Never go below 14px for any text

The minimum readable font size on mobile is 14px (--font-size-small). This applies to captions, helper text, timestamps, and badge labels.

close

Avoid long lines of text

On mobile's narrow viewport, text naturally wraps shorter. Avoid fixed-width containers that force horizontal scroll. Let text flow to the viewport edge with 16px margins.

Best Practices

check

Use 16px (--spacing-sm) as the mobile layout unit

Page margins, card internal padding, and gaps between sections should all use 16px on mobile. This creates consistent rhythm without wasting valuable screen space.

check

Single-column layout

Mobile views use a single-column layout. Avoid side-by-side arrangements that worked on desktop — stack them vertically instead.

close

Don't use spacing larger than --spacing-md (24px) for internal gaps

Larger spacing tokens (32px+) should be reserved for major section breaks on mobile. Overusing them wastes limited vertical scroll space.

Best Practices

check

44×44px minimum for all interactive elements

Per WCAG 2.5.8 (Target Size), all touch targets must be at least 44×44px. Even if the visual element (icon, text) is smaller, the tappable area must meet this minimum.

check

8px minimum gap between touch targets

Adjacent interactive elements must have at least 8px (--spacing-xs) of separation to prevent mis-taps.

close

Don't rely on hover states

Touch devices have no hover. All hover-dependent interactions must have tap equivalents. Tooltips should be replaced with inline help text or info icons that open on tap.

Best Practices

check

Make primary CTAs full-width on mobile

Primary action buttons should span the full container width on mobile. This maximizes the touch target and provides visual clarity about the primary action.

check

Stack buttons vertically

When multiple buttons appear together, stack them vertically with 8px gaps. Primary action on top, secondary below. Avoid side-by-side button groups on mobile.

info

Consider sticky bottom actions

For primary form submissions or navigation actions, a sticky bottom bar keeps the CTA visible regardless of scroll position. Use with restraint — only for the single most important action per screen.

Best Practices

check

Use appropriate input types

Use type="tel", type="email", type="number" etc. to trigger the correct mobile keyboard. This significantly improves data entry speed and accuracy.

check

Full-width inputs

All form inputs should be 100% width on mobile. Avoid side-by-side field arrangements unless strongly related (e.g., first name / last name, and only if labels remain clear).

close

Don't use placeholder text as labels

Placeholder text disappears on input focus, leaving users without context. Always use visible labels above inputs. Placeholders may supplement labels with example values.

Navigation Patterns

Mobile navigation and layout structure.

Best Practices

check

Use bottom navigation for primary actions

Bottom tab bars are within thumb reach and follow mobile platform conventions. The Yazaki mobile prototype uses a fixed bottom nav with Home, Requests, Profile tabs.

check

Collapsible sidebar for secondary navigation

Replace the desktop sidebar with a hamburger menu or bottom sheet on mobile. Keep the primary content area as wide as possible.

info

Viewport meta tag

Always include <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no"> to prevent unexpected zoom and ensure consistent rendering.
