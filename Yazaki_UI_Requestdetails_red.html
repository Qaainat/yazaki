Refactor Rationale — Screen A

  • ✓Labels changed from interactive blue (#008C95) to muted gray ($font-color-label: #6c717e) — blue reserved for actual clickable elements only
  • ✓Yellow-bordered Mendix widget placeholders replaced with clean "—" / "Not provided" text — consistent read-only display state across all fields
  • ✓Status "Created" promoted to semantic badge (navy chip) — scannable at a glance, consistent with all status treatments across the application
  • ✓Breadcrumb added (Request List › TR26-6) — establishes context and provides back navigation independent of browser
  • ✓Card headers use uppercase label + separate Edit button — cleaner visual separation of content and action zone per card
  • ✓Active tab uses 3px Yazaki Red underline — replaces blue underline with brand-correct treatment consistent with topbar stripe
  • ✓Left rail extended to full navy height — integrates with topbar chrome, eliminates the isolated icon strip look
  • ✓Red warning note converted to amber left-border callout — red text reserved for actual errors, not informational notes
  • ✓Empty state for Supporting Documents shows icon + instructive message — "No Items Found" plain text replaced with functional empty state
  • ✓Button border-radius 30px → 4px — eliminates pill-shaped buttons throughout
  • ✓Heading hierarchy established: 18px page title, 12px uppercase card headers, 11px field labels — three distinct tiers

Refactor Rationale — Screen B

  • ✓Admin nav moved from 2-row horizontal overflow into grouped left sidebar — eliminates wrapping, groups related tools, provides consistent navigation chrome across all views
  • ✓Status filter tabs promoted to properly styled filter row with count badges — active tab uses 3px Yazaki Red underline + count badge turns red; inactive tabs use muted text
  • ✓Double horizontal scrollbar eliminated — removed min-width: 1400px on .RequestDataContainer, grid uses width: 100% relative to its container
  • ✓Status values converted to semantic color badges — "Test In Progress" blue, "Waiting on Deliverables" amber, "Received by Lab" teal — scannable at a glance
  • ✓Selected row now uses blue tint ($dg-brand-light: #dff2f3) — replaces red left-border which conflicted with the Yazaki Red brand use; blue tint is clearer selection affordance
  • ✓Column header "External I D" fixed to "External ID" — minor but signals attention to quality
  • ✓Action buttons differentiated: info (ⓘ) is neutral, delete (🗑) gains danger hover state — destructive action is visually distinct without adding friction
  • ✓Global search box added above the filter row — prominent search complements per-column filters for users who know what they're looking for
  • ✓Column filters use consistent input styling (border-radius: 3px, $bg-color background) — replaces mismatched filter inputs
  • ✓Result count + pagination added — users know how many records match and can navigate without scrolling to find the bottom
  • ✓"New Request" primary button promoted to top-right of toolbar — currently no visible entry point for creating a request from the list view

Mendix Component Opportunities

  • ▸Admin Sidebar Navigation Page TemplateShared Pattern
    Named Mendix Atlas sidebar layout with grouped sections. Apply to all manager-role pages. Replaces the horizontal nav overflow pattern entirely.
  • ▸Status Filter Tabs Building BlockSCSS Pattern
    Tab group with count badge. .aft-filter-tab.active pattern — 3px Yazaki Red underline, navy text. Reuse on all multi-status list pages.
  • ▸Data Grid with Search + Toolbar Page Template
    Full list page template: sidebar + content area + toolbar (search, count, actions) + grid + pagination. The canonical Mendix list page pattern for this application.
  • ▸Status Badge (Semantic Colors) Utility ClassSCSS Pattern
    Shared class map: .badge-progress / .badge-waiting / .badge-received / .badge-approved / .badge-rejected. Define once in _yazaki_variables.scss.
  • ▸Grid Action Column Building Block
    Standard 2-button action column: View (neutral) + Delete (danger on hover). Consistent placement and sizing across all data grids.
  • ▸Pagination Bar Building BlockSCSS Pattern
    Standardized pagination with result count, page buttons using $brand-primary for active state. Replaces current scattered pagination implementations.

Next Steps These designs are ready for client review. Once approved, implementation should follow this sequence: (1) Apply custom-variables.scss token changes — buttons, typography, border radius — which will propagate across all pages simultaneously; (2) Build the sidebar navigation as a Mendix Atlas layout and apply it to manager-role pages; (3) Create the Key-Value Read Panel and Status Badge building blocks in Mendix Studio Pro; (4) Fix the .RequestDataContainer min-width scroll issue; (5) Apply Status Badge pattern to all data grids across the application. Remaining screens (DUT Details, Requested Tests, Spec Chapter Edit) should follow the same building blocks once those are established.
