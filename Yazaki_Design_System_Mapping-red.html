Website Elements — Do Not Carry Into Enterprise App
Patterns from yazaki-na.com that are not appropriate for this application
The Yazaki NA website could not be fetched directly. The following flags are based on standard patterns typical of Yazaki's web presence and Yazaki brand documentation, combined with knowledge of what does and does not translate from marketing sites to enterprise data applications.
Full-bleed hero imagery
Large product photography (connectors, wire harnesses) with overlaid text. Appropriate on the marketing site — not appropriate inside an authenticated data application. The one product photo (Connectors.png) should be confined to login/welcome screens only, not used as page backgrounds in functional areas.
Marketing typography scale
Website H1s at 48–72px with tight tracking. In the enterprise app, font sizes above 24px belong only in empty state illustrations or welcome messages — never in data-entry or review workflows. The existing heading scale in Atlas Core is already too large; we are proposing to reduce it further (see Section 03).
Animated transitions / scroll effects
The public website likely uses scroll-triggered animations and parallax. These are inappropriate in a workflow application — they introduce perceived latency and are disorienting in task-focused contexts. Limit animation to: the flyout slide-in (existing, keep), loading state spinners, and toast notifications only.
Yazaki Red as primary action color
The website likely uses Yazaki Red prominently for CTAs and navigation highlights. In the enterprise application, red must be reserved for brand accents (topbar stripe, checkbox/radio fills) — using it for interactive buttons will cause user confusion with danger/error states, especially in the approve/reject workflow.
Dark section backgrounds
Marketing sites often alternate white and dark navy section backgrounds for visual rhythm. This pattern does not translate to application UIs where the navy is strictly reserved for the nav chrome. Application content areas must use the light surface hierarchy (Layer 1–3) only.
Wide-spaced, low-density layouts
Marketing pages optimize for impact and readability at a glance. This application must optimize for data density — users spend hours in request list grids and spec review tables. Marketing whitespace values would require excessive scrolling in real-world use. Use the spacing scale conservatively.
Non-standard icon libraries
If the website uses a custom Yazaki icon set, do not carry it into the Mendix application. Use the Atlas Core Mendix icon system (Atlas Icons or a single agreed icon library) to ensure Mendix widget integration. Mixing icon families is a primary visual inconsistency source.
Multiple decorative font families
Marketing sites often pair a display typeface with a body font. Open Sans already in the application is correct for enterprise use. Do not introduce a display or heading-only font — it increases the font load, conflicts with Mendix text widget rendering, and is unnecessary in a data-dense application context.

Implementation Notes
How to apply this system once approved

Recommended implementation sequence

Step 1 — Variable Approval
Review this document with the client. Confirm proposed values. Identify any deviations from actual brand guidelines. Approve the mapping before any code is written.
Step 2 — Write custom-variables.scss
Apply all proposed values to theme/web/custom-variables.scss (the override file). Do not edit atlas_core/web/_variables.scss directly — that file is owned by Mendix and will be overwritten on Atlas updates.
Step 3 — Promote to _yazaki_variables.scss
Add new named Yazaki brand variables ($YazakiNavy, $brand-success-dark, etc.) to themesource/module_ui/web/_yazaki_variables.scss rather than scattering them across component files.
Step 4 — Consolidate modules
Merge duplicate flyout/home/list implementations from module_ui and module_testingportal into a single canonical implementation in module_ui. Module_testingportal should only contain page-specific overrides, not layout foundations.
